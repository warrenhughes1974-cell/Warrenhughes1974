## 1. Method — controlled A/B, not a stale snapshot

The first regression pass compared the new Output against the **2026-08-28 batch snapshot**
(`evidence/pre_fix_rates/`). That baseline was produced by a different code state, so any
difference it showed could not be attributed to Issue #158 with confidence — and in fact it
falsely implicated plan `9SUBLF`.

To isolate this fix, a kill switch was added (see section 2) and rates were regenerated twice
on the **same commit, same source extracts, same valuation date**:

| Run | Env | Output captured to |
|---|---|---|
| Baseline | `QLA_PR_SEGMENT_SLOT_OWNERSHIP=0` | `evidence/baseline_off_rates/` |
| Fixed | default (switch on) | `QLA_Migration/Output/rates/` |

The only variable between the two runs is this issue's fix. `9SUBLF` does **not** appear in the
controlled comparison — it was an artifact of the stale baseline, unrelated to Issue #158.

Comparison script: `_regression_compare_rates.py` (full-row multiset per table).
An earlier version of that script keyed rows on the QuikGps dimension columns, which the
`QuikPl*` member/key tables do not carry, collapsing all their rows into one bucket and hiding
real differences. It now compares complete rows.
